## Covered behavior

- v5 이하 세이브를 v6로 정규화하고 미처리 개표 진행을 기본 0으로 복구한다.
- 30초 이상 지난 저장 복귀가 신규 게임 fallback으로 바뀌지 않고 실제 세이브에서 오프라인 정산된다.
- 오프라인 표는 현재 구역의 남은 진행을 채우고 초과분은 `offlineCarryVotes`에 보관된다.
- 표 자원과 누적 통계는 한 번만 지급되고, 이월은 이후 구역의 진행도에만 적용된다.
- 8시간 복귀 이월은 3구역 보스와 완료 후 작전회의에서 각각 멈춘다.
- 하루 1회 2배는 표·해명과 이월을 같은 양만큼 한 번 더 적용하고 당일 재사용을 막는다.
- 정산 직후 10초 자동저장 전에 새로고침해도 같은 부재 보상과 이월을 다시 지급하지 않는다.
- 정산 모달은 현재 구역 반영량과 다음 지역 이월량을 구분한다.
- 감사 탭과 확인 모달은 현재 대비 영구 생산 증가율과 `조금 더 / 감사 적기 / 강력 추천`을 표시한다.
- 390×844와 1280×900에서 overflow가 없고 정산 CTA는 최소 44px를 유지한다.

## Bug found during real return test

- 저장된 세이브로 장시간 복귀할 때 `cpsFor(data)`가 생성 전 `this.data`를 캐릭터 효과 경유로 읽어 예외가 발생했고, 넓은 load fallback이 이를 신규 게임으로 대체했다.
- 캐릭터 효과 조회가 계산 대상 data를 선택적으로 받게 수정하고, 1시간 저장 복귀 회귀 테스트를 추가했다.
- 신규 세이브·실시간 CPS·클릭·사건 경로의 기존 기본 호출은 유지했다.

## Remaining risk

- 이월량은 지역 완료를 누를 때마다 적용되므로 매우 긴 복귀 뒤에는 사용자가 여러 번 완료·보스·작전을 진행해야 한다. 이는 능동 게이트 보존을 위한 승인된 설계다.
- 클라우드보다 로컬 세이브가 오래된 실제 다기기 경합은 기존 클라우드 회귀 범위이며 이번 로컬 이월 E2E에서 새로 재현하지 않았다.
- Phaser와 Firebase 관련 기존 500kB 초과 청크 경고는 다음 모바일 성능 단계의 대상이다.
