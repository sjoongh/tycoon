# 믿어주세요 개표국 — 비주얼·시스템 고도화 설계

작성 2026-10-21. 대상 버전 1.1.2 → 2.0.0.

## 1. 의도

현재 빌드는 기능은 많지만 "진짜 게임"처럼 보이지 않는다. 소유자의 진단은 "아이콘들 개별로"다. 코드 조사 결과 원인은 디자인 취향이 아니라 아트 자산이 없다는 사실이다.

- 시설·탭·직원 아이콘이 10~16px 도트맵(`src/world/dotChar.js`)을 SVG data URI로 뻥튀기한 것
- 국장 캐릭터·칭호·뽑기·아이템·지역 아이콘은 OS 이모지라 기기마다 다르게 보이고 픽셀 화풍과 충돌
- 월드(위쪽 절반, 390×~470)는 빈 암적색 그라데이션 위에 16px 국장을 6배, 16px 소품을 4배 확대해 놓은 상태. 방·바닥·벽·동선이 없음
- 성장 시스템(직원·칭호·캐릭터·감사·작전·도감)이 전부 `cpsFor()`의 생산 배율 한 버킷으로 합산돼 빌드 선택이 무의미(2026-07 Codex 리뷰 #7과 동일)
- 시설은 "N구역 도달"로만 해금되고 시설 간·직원 간 선행 조건과 상한이 없음
- 시계는 `Date.now()` 단독 의존, 세이브는 로컬·네이티브 미러·Firestore를 `lastSavedAt` 비교만으로 채택

`assets/design/service-ui-target.png`는 소유자가 스켈레톤 수준이라 판단해 폐기한다. 레퍼런스는 다른 타이쿤 게임에서 다시 잡는다.

## 2. 목표 · 비목표 · 실패 조건

목표
1. 모든 아이콘과 스프라이트가 한 팔레트·한 해상도 규칙을 따른다. 이모지 0개.
2. 월드가 "운영되는 개표소"로 읽힌다. 시설 레벨·배치 직원·병목이 화면에 즉시 반영된다.
3. 시설·직원 간 선행 조건과 상한이 생기고, 생산에 병목 개념이 들어가 빌드 선택이 의미를 가진다.
4. 난이도 곡선이 후반에 실제로 조여진다.
5. 세이브가 시계 조작·기기 간 경합에서 보상 중복이나 진행 손실 없이 동작한다.
6. 매초 DOM 전체 재생성을 없애고 값만 갱신한다.

비목표
- 게임의 풍자 테마·자원 3종(표/해명/믿음)·구역 진행·감사 프레스티지 구조는 바꾸지 않는다.
- 광고·IAP는 이 설계 밖(별도 작업).
- 런타임에 외부 이미지 생성 API를 부르지 않는다. 생성 도구는 자산을 뽑아 리포에 넣는 파이프라인으로만 쓴다.

실패 조건
- 아트는 예쁜데 기존 세이브 v9가 로드되지 않거나 진행이 깎인다.
- 아이콘을 바꿨는데 월드는 여전히 빈 바닥이다(부분 교체는 더 어색하다).
- 난이도를 올렸는데 첫 감사까지 걸리는 시간이 `scripts/_balancesim.mjs` 기준 2배 넘게 늘어난다.

## 3. 제약

- 스택 유지: Phaser 3.90 커스텀 코어, DOM UI(`src/ui/*`), Vite, Capacitor 8, Firebase 익명 로그인+Firestore.
- 세로 390×844 기준. Android WebView에서 이모지·시스템 폰트 폴백을 신뢰할 수 없다(기존 수정 이력 다수).
- 번들 예산: 초기 로드 아트 합계 ≤ 400KB(webp). Phaser 번들 1.2MB는 이미 부담.
- 라이선스: CC0 또는 상업 이용 가능 라이선스만. 출처·라이선스는 `public/art/CREDITS.md`에 기록.
- 기존 132개 테스트는 계속 통과해야 하고, 세이브 v9 → v10 마이그레이션 테스트가 추가돼야 한다.

## 5. 게임 시스템

### 5.1 선행 조건과 상한 (연관관계·제한)
데이터 필드를 추가하고 `GameState.isUnlocked / canHire / staffMaxLevel`이 이를 읽는다.

시설 `requires`:
| 시설 | 구역 | 선행 |
|---|---|---|
| desk 접수창구 | 1 | 없음 |
| sorter 투명분류함 | 1 | desk ≥ 5 |
| notice 안심공지판 | 2 | sorter ≥ 5 |
| server 조용한서버실 | 3 | notice ≥ 8, engineer 채용 |
| archive 기록보관소 | 4 | server ≥ 10, auditor 채용 |
| studio 브리핑룸 | 5 | archive ≥ 10, speaker 채용 |

직원 `worksAt`과 상한:
- 직원은 담당 시설이 Lv.1 이상이어야 채용 가능(clerk→desk, runner→sorter, analyst→notice, engineer→server, auditor→archive, speaker→studio).
- 직원 레벨 상한 = min(20, 담당 시설 레벨). "Lv.5 창구에 Lv.15 접수원"이 불가능해진다. 기존 세이브에서 초과분은 깎지 않고 `capped` 표시만 하며 다음 승급이 막힌다.
- 배치 슬롯은 3 → 구역 6·12에서 각 +1(최대 5).

### 5.2 처리 용량과 적체 (병목)
생산 사슬을 접수 → 분류 → 기록으로 명시한다.
- `intake` = desk 기반 생산(현재 cps 구성 중 desk·server·click 분)
- `capacity` = sorter·archive·runner·engineer가 만드는 초당 처리 상한
- 초당 `min(intake, capacity)`만 표로 확정되고, 초과분은 `backlog`(적체)에 쌓인다.
- 적체는 믿음을 추가로 깎는다(적체/용량 비율 × 0.02/초, 상한 0.1). 적체는 다음 틱의 남는 용량으로 자동 소화된다.
- UI: 시설 카드에 "용량 n/초", HUD 아래 적체 경고 바. 월드에 표 더미.
- 오프라인 정산은 `min(intake, capacity)`로 계산(적체 누적 없음, 대신 보상이 용량에 묶인다).

이 하나로 "접수창구만 올리는 빌드"가 깨지고, 분류·기록·운반 직원이 생산 배율이 아닌 **별개 축**이 된다.

### 5.3 성장 축 분리
`cpsFor()` 한 식에 더해지던 효과를 네 축으로 나눈다.
- 생산(intake): 시설, 감사 업그레이드 cpsPct
- 용량(capacity): sorter·archive·runner·engineer·작전 build 계열
- 회복(trust): notice·auditor·speaker·브리핑·작전 response 계열
- 조작(click/fever): clerk·캐릭터·칭호 click·작전 tap 계열

칭호·캐릭터는 배율이 아니라 규칙 변경으로 바꾼다. 예: 열혈 국장 = 피버 지속 +4초/회복 -10초, 초연 국장 = 적체 믿음 페널티 반감, 정석 국장 = 사건 선택 결과 미리보기.

### 5.4 난이도
- 구역 목표 지수 1.38 → 구역 7부터 1.5. 첫 감사(구역 6) 도달 시간은 유지.
- 믿음 자연 감소 0.06 → 0.06 + 0.004 × (구역-1), 상한 0.12.
- 보스 실패 시 보상 없음 + 적체 +30%(현재는 건너뛰기 가능). 건너뛰기는 유지하되 해명 비용.
- 사건 주기 45초 → 2~4분, 최대 3개 큐. 방치 중 발생한 사건은 복귀 시 일괄 제시.
- 시설 레벨 마일스톤 [25,50,100] → 시설별 데이터화, maxLevel 초과 마일스톤 금지.

### 5.5 시계
`src/state/ClockService.js`
- `now()`는 `Date.now() + offset`. offset은 클라우드 초기화 때 Firestore `serverTimestamp()` 왕복으로 1회 측정(실패 시 0).
- 저장 시 `lastSavedAt`은 ClockService 기준. 로드 시 로컬 시계가 `lastSavedAt`보다 1시간 넘게 과거면 "시계 이상" 상태: 오프라인 보상·출석·일일 퀘스트 지급 보류, 정상 복귀 시 재개.
- 모든 `Date.now()` 호출(GameState 30여 곳, DOM 몇 곳)을 ClockService로 치환.

### 5.6 세이브
`src/state/SaveService.js`로 분리.
- 단일 채택 경로 `adopt(candidate, source)`: 로컬·네이티브 미러·클라우드 후보를 모아 `(lastSavedAt, stats.totalVotes)` 사전식 비교로 1회 선택 → normalize → offlineProgress 1회.
- 세이브 버전 10: `requires/worksAt` 관련 파생값은 저장하지 않고 로드 시 계산. `backlog`, `clock` 필드 추가. v9 로드 테스트 포함.
- 클라우드 쓰기는 10초 디바운스 + 구매·감사·구역 완료 직후 즉시.
- 숫자 필드는 `finiteOr()`로 정규화(0 보존).

### 5.7 실시간 갱신
- `changed` 이벤트를 `economy`(매초 숫자), `structure`(구매·해금·배치), `tab`으로 분리.
- 하단 패널은 structure 때만 innerHTML 재생성, economy 때는 `data-k` 노드의 textContent·style만 갱신.
- 월드는 structure 이벤트로 티어·직원 스프라이트 교체, economy로 적체·숫자만.

## 6.5 구현 기록 (2026-10-21)
- P1·P2·P3 구현 완료. 16px 아이콘은 game-icons 글리프가 뭉개져 포기하고 32px 단일 소스(1x/2x 표시)로 확정. 월드는 3x 전역 배율.
- 선행 조건은 시설→시설만(서버실↔전산관 같은 순환 방지). 직원은 담당 시설(worksAt) Lv.1 필요, 상한 = min(20, 시설 레벨). 기존 세이브 초과분 보존.
- 용량 가중치(capacity): desk 0.5 · sorter 1.8 · notice 0.6 · server 1.0 · archive 1.6 · studio 0.9. 운반 +5%/Lv, 전산 +4%/Lv, 검수 +2%/Lv는 용량에만. 적체 믿음 페널티 = 적체/분당용량 × 0.05/초(상한 0.1).
- 보스 실패·건너뛰기 페널티는 해명 비용 대신 적체(용량 30초분, 하한 50). 사건 주기 45초는 유지(밸런스 시뮬이 45초 주기를 전제).
- 밸런스 시뮬(`npm run test:balance`): 첫 감사 644초(목표 480~720), 반복 423·457초(목표 300~480), 깊은 런 11구역 1398초(기준선 1395초). 난이도 상승은 구역 7 이후 지수 1.5로만 반영.
- 세이브 v10: `backlog` 추가. v9 로드 테스트 통과.
- P4: `src/state/clock.js`(서버 보정 오프셋, Firestore serverTimestamp 왕복 1회), GameState의 Date.now() 41곳 치환, 시계 되감김(1시간) 시 출석·주간 보상 보류. `src/state/saveWinner.js` 승자 규칙을 클라우드·네이티브 미러 공통 적용. persist 이벤트 → 10초 디바운스 클라우드 저장, pagehide flush.
