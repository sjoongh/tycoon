# Claude Fable 5 계획 리뷰 패킷

## 목표
모바일 방치형 Phaser 게임에서 연타 중 DOM 전체 재생성을 줄이고 초기 전송 경쟁을 완화한다. 게임 경제·기능·현재 시각 정체성은 보존한다.

## 사용자 제약
- 직접 플레이하고 실제 오류를 계속 잡는다.
- 적절한 스킬과 Claude를 함께 사용한다.
- 이전 페이즈는 모두 `main`에 병합됐으며 사용자 소유 `.omc/`, `.impeccable/`는 건드리지 않는다.

## Codex 독립 분석
1. `GameState.processClick()`은 탭마다 `changed`를 발생시킨다.
2. `DOMBottomPanel`은 모든 `changed`에서 활성 탭을 `innerHTML`로 전부 교체한다.
3. `DOMHud`는 모든 변경에서 반복 querySelector와 FAB `innerHTML` 교체를 수행한다.
4. 감사 인장 선택 핸들러는 `_renderPrestige()`를 연속 두 번 호출한다.
5. Firebase SDK는 동적 청크지만 설정이 켜져 있어 시작 직후 `initCloud()`가 불러온다.
6. Galmuri 9/11/14와 Press Start 2P가 모두 초기 화면에서 사용되어 실제 폰트 전송이 약 1.51MB다.
7. Phaser 1.21MB 청크는 게임 자체의 필수 런타임이므로 이번에 억지로 지연시키지 않는다.

## Codex 계획
1. `changed`가 연속될 때 하단 패널 렌더를 100ms 예산으로 합치되, 패널 내부 직접 조작은 즉시 강제 렌더한다.
2. 예약 렌더는 destroy에서 해제하고 스크롤 복원을 유지한다.
3. HUD의 자주 쓰는 노드를 생성 시 캐시하고 동일한 FAB 마크업은 다시 쓰지 않는다.
4. 감사 탭 인장 선택의 이중 렌더를 한 번으로 줄인다.
5. Galmuri11 하나를 한글 UI 공통 패밀리로 사용해 9/14 다운로드를 제거한 뒤 360/390px 스크린샷으로 선명도·오버플로를 확인한다. 실패하면 폰트 축소는 폐기한다.
6. Firebase 초기화 지연은 클라우드 세이브 충돌 위험 때문에 우선 보류한다. 폰트 절감과 DOM 병목 개선 후에도 필요할 때만 제한적으로 적용한다.
7. 동일 성능 스크립트, 68개 단위 테스트, 빌드, 기존 네 E2E, 실제 연타 플레이로 검증한다.

## 리뷰 요청
- 계획에서 놓친 정확성·접근성·모바일 WebView 회귀 위험이 있는가?
- 100ms 렌더 합치기가 안전한가? 더 나은 최소 변경이 있는가?
- 폰트 단일화의 장단점과 검증 기준은 적절한가?
- Firebase 초기화 보류 판단은 타당한가?
- 성공 기준과 롤백 조건을 구체적으로 제안해 달라.
