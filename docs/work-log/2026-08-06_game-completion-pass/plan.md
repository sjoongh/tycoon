# Plan — 게임 완성도 마감 패스

## 목표

직원 전략 배치·승급, 고레벨 외형, 안전한 PWA 갱신, 균형형 감사 곡선이 저장 호환과 E2E를 통과하고 Firebase 운영에 배포된다

## 작업 범위

1. 직원 데이터·GameState·직원 탭·WorldView를 연결해 3개 배치 슬롯과 5레벨 단위 승급을 구현한다.
2. 기존 기본 효과를 보존하면서 배치 고유 능력만 경제식·사건·클릭에 가산한다.
3. 시설 t4/t5와 직원 승급 외형을 기존 런타임 도트 텍스처 체계 안에서 구분한다.
4. 192/512 PNG·마스커블 아이콘과 PWA 스크린샷, 서비스 워커 업데이트 선택 UI를 구현한다.
5. 첫 감사 8~12분·이후 5~8분을 자동 판정하는 시뮬레이션을 만들고 병목·보상을 조정한다.
6. README·manifest·Firebase Hosting 설정과 QA 추적성 문서를 최신화한다.
7. 단위·PWA·모바일/데스크톱 E2E·장기 실플레이·회귀를 실행하고 교차 리뷰한다.
8. 미리보기 채널 smoke test 후 운영 배포하고 PR·원장·worktree를 정리한다.

## 검증 계획

- `npm test`와 신규 직원·경제 단위 테스트.
- `npm run build`와 manifest/아이콘/service-worker 정적 검증.
- `QA_BASE_URL=http://localhost:5178` localhost target guard 후 Playwright 직원 배치·승급·업데이트 E2E.
- 첫 감사 및 후속 런 결정적 시뮬레이션, 10분 이상 자연 실플레이.
- 기존 오프라인·보스·작전·피버·사건 체인·가독성·모바일 성능·시작 회귀.
- Firebase preview URL smoke test와 운영 URL 배포 상태 확인.

## 위험

- 배치 보너스가 기존 모든 직원 효과와 곱해져 후반 경제가 폭주할 수 있다.
- 첫 감사 시간을 늦추는 조정이 초반 무반응 구간을 만들 수 있다.
- 세이브 v7에 없는 배치 상태의 기본값과 감사/전복 보존 규칙이 엇갈릴 수 있다.
- 서비스 워커 `skipWaiting`이 사용자 선택 전에 실행되면 안전한 갱신 계약이 깨진다.
- Firebase 설정을 `dist`로 바꿀 때 기존 `/privacy.html`이 누락될 수 있다.
- 배포는 prod 트립와이어이므로 미리보기 검증과 독립 교차 리뷰 없이는 실행하지 않는다.
