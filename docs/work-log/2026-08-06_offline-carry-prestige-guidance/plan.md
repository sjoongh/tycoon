# Plan — 오프라인 이월·감사 판단 개선

## 완료 조건
- 오프라인 초과분이 저장·재접속·2배 수령을 거쳐도 구역 진행 크레딧으로 보존된다.
- 지역 완료 때 다음 지역에 이월되고 체크포인트 보스·작전은 건너뛰지 않는다.
- 복귀 정산과 감사 실행 전 사용자가 보상·증가율을 바로 이해한다.
- 단위 테스트, 빌드, E2E, 모바일·데스크톱 실플레이가 통과한다.

## 구현 순서
1. 저장 상태와 정규화 경계를 추가한다.
2. 기본/2배 오프라인 정산의 진행 반영·이월 계산을 공통화한다.
3. 지역 전환 시 이월을 새 목표에 적용한다.
4. 복귀 모달과 감사 탭/확인 모달을 정리한다.
5. 단위·E2E·실플레이 후 QA 증적을 갱신한다.

## 테스트 전략
- 정상: 일부 진행에서 1시간 보상, 완료 상태에서 보상, 지역 완료 후 이월.
- 경계: 30초 미만, 8시간 cap, 구 세이브, 큰 수, 이미 완료된 체크포인트.
- 오류 방지: 기본+2배 중복, 저장 재로드, 감사 초기화, 보스·작전 순서.
- UI: 360/390/1280px overflow, 44px 버튼, reduced-motion, 정산/감사 문구.

## 위험
- 이월분은 이미 총표에 포함되므로 새 지역에서 다시 자원으로 지급하면 경제가 두 배가 된다.
- `advanceStage()`의 완료 보상과 이월 적용 순서가 뒤섞이면 진행도가 왜곡될 수 있다.
- 오프라인 복귀 모달은 일일·알림 모달과 직렬 순서를 유지해야 한다.
