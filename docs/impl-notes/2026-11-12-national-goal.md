# 전국 합산 목표 (레퍼런스 로드맵 장기 #5)

이번 주 전체 플레이어의 **사건 대응 수**를 합산하는 공동 목표다. 표는 지수적으로 커져서 사람마다 수십억 배 차이가 나므로 합산 단위로 쓰지 않았다. 사건은 45초 쿨다운이 있어 플레이 시간에 비례한다.

## 규칙
| 항목 | 규칙 |
|---|---|
| 내 기여 | 이번 주 사건 대응 수 = 평생 사건 수 − 주 시작 기준점(`weekly.baseEvents`). 감사·전복에도 평생 통계가 유지되므로 이어서 센다. 기준점이 없던 세이브는 업데이트 시점부터 센다 |
| 합산 | `scores/{uid}` 문서에 `weekEvents`를 함께 올린다(5분 주기 + 세션 시작 + 랭킹 열기). 닉네임을 정한 플레이어만 들어간다 |
| 단계 | 300 / 1000 / 3000 / 8000건 → 해명 60 / 120 / 200+인장 1 / 300+인장 2. 단계마다 시즌 +20 |
| 받기 | 이번 주 직접 처리한 사건이 3건 이상이면 랭킹 '이번 주 개표' 탭에서 받는다. 닉네임이 없어도 받을 수 있다 |
| 알림 | 합산이 새 단계를 넘으면 받을 자격이 있는 사람에게 한 번만 알린다 |
| 지난주 | 주가 넘어갈 때 덜 받은 단계가 있으면 정산 대기로 두고, 다음 클라우드 연결 때 그 주 합산으로 자동 지급한다 |
| 상한 | 1인 주간 상한 13,440건(7일 × 45초 쿨다운). 서버 합계가 `참여자 × 상한`을 넘거나 집계가 실패하면 문서를 받아 1인 상한으로 잘라 다시 더한다 |

## Firestore
- 집계 `sum(weekEvents) + count()` where `week == 이번 주`는 복합 색인(week, weekEvents)이 필요하다. `firestore.indexes.json`을 추가하고 `firebase deploy --only firestore:indexes`로 배포했다(보안 규칙은 건드리지 않음).
- 색인에는 `weekEvents`가 있는 문서만 들어간다. 이전 버전 앱의 점수 문서는 합산·참여자 수에서 빠진다.
- 보안 규칙은 본인 점수 문서 쓰기만 검사한다. 조작된 값이 합산을 부풀릴 수 있는 위험은 위 상한 검사로 줄였지만 막지는 못한다(기존 주간 순위와 같은 수준).

## 검증
- `npx vitest run` 282건 통과(전국 목표 신규 10건). `npm run build` 통과. 개발용 `window.__gpCloud` 훅은 배포 번들에 없다.
- Playwright(개발 서버, Firebase 호출 차단)로 패널 3상태(받기 가능 / 3건 미만 / 전 단계 수령)와 받기 클릭 후 상태를 확인했다.
- 라이브 Firestore: 색인 배포 직후 `CREATING` 상태로 서버 집계가 거절됐다. 이 동안은 문서 합산 경로로 동작한다.

## 아직 확인할 것
- 단계 수치는 현재 주간 참여자(약 10명) 기준 설계값이다. 실제 주간 합산 분포는 미측정이다.
- 서버 집계 경로는 색인 생성 완료 후 확인한다.
